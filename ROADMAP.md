# Roadmap

> Phase-based with dependency tracking. Tasks within a phase are independent.
> Statuses: `TODO` | `IN PROGRESS` | `DONE`
> Priorities: `P0` (must have) | `P1` (should have) | `P2` (nice to have)
> Sizes: `[S]` (small) | `[M]` (medium) | `[L]` (large — consider splitting)
> Flags: `[SPIKE]` — needs investigation before implementation; `[BLOCKED: reason]` — waiting on external dependency
> Dependencies: `depends: #x, #y` — all must be complete before task starts
> Scope: `scope: path/` — relevant files/directories for the task (required)
> Acceptance: `AC:` — machine-verifiable criteria (indented below task)
> Milestones: `MILESTONE:` — marks demo-able project states
> Completed phases are collapsed to one-line summaries.

## Tech Stack
- Language: Python 3.13 (uv-managed)
- Framework: typer CLI · httpx · pydantic · SQLite · polars/numpy/scipy · Playwright for Python (installed Edge/Chrome channel) · anthropic SDK · FastMCP
- Key conventions: follow `CLAUDE.md` invariants. Workers propose and only `executor/` writes to ESPN. **No live ESPN writes during development** (`--dry-run` only). League settings are data. Projections are stat lines. Selectors live only in `src/fm/browser/selectors.py`. Design reference: `docs/DESIGN.md`.
- Shared-file rules:
  - #1 declares every v1 dependency, so later tasks never edit `pyproject.toml` or `uv.lock`.
  - CLI command groups are auto-discovered from `src/fm/commands/` (one file per group), so tasks never edit `cli.py`.
  - #3 defines the full v1 schema.
  - Decision modules register via `src/fm/decide/registry.py` (#7); executor flows register via `src/fm/browser/flows/__init__.py` (#19).
- Build: `uv sync --locked`
- Test: `uv run pytest -q`
- Lint: `uv run ruff check . && uv run pyright`
- Dev: `uv run fm --help`

## Phase 5 — DONE
Built: `fm.decide.lineup` (#20) solves a week's NFL lineup as an assignment problem (`scipy.optimize.linear_sum_assignment`) in priority order: every active slot filled with a player who will play (an OUT, bye or no-game starter is benched whenever any legal arrangement, including shifting starters between slots, replaces him; empty slots filled), then expected points (`p_active` × the league's own scoring of the period's stored lines, blended in memory with `data/blend_weights.toml`), then the fewest moves; with an opponent outlook it switches to win probability (normal approximation; a search over expected + w·variance seeded from the expected-points lineup, so the switch never lowers P(win)) when the expected-points lineup wins with P ≥ 0.75 or ≤ 0.25; locks are hard constraints (ESPN `lineupLocked` at the last sync, or `plugin.locks(period, schedule, lock_type=settings.lineup_lock_type)` passed; a bye never locks per game; `UNKNOWN` raises `LineupError`), IR players stay put and nobody moves to IR; `plan_lineup` reads the roster snapshot, the `players` rows, the projection lines and availability (a stored row no older than the player row, else `assess()`, for `p_active` only; whether he has a game comes from the schedule in hand, never the row, which may have been assessed without one; OUT, IR, suspended, off-roster or without a game is 0), and `propose_lineup` drafts up to two `LineupPayload` proposals against the synced roster (`bench_inactive`: the best lineup that keeps every playing starter; `lineup`: the full optimum when it goes further), each with a deadline (the earliest lock among the moved players), engine numbers, a template rationale and a dedupe key, through `fm.proposals.propose` (policy refusals reported, never raised), registered as `("nfl", "lineup")`. `fm.model.valuation` (#21): `PlayerOutlook` weekly expected points (this week's blend × `p_active`; later weeks ESPN's `102026` season line per game × that week's games × `health`, the projected `GP` over the games left), `start_value` as a max-weight slot assignment with later-week holes filled at replacement level, replacement level from the league's actual wire, ROS value with playoff weeks weighted up, `LeagueValuation` / `load_valuation(include_rostered=...)`, `slot_instances`, `eligible_active_slots`; settled that `102026` (split 0) is ESPN's rest-of-season line and `122026` is unread (docs/espn-api.md section 1 #10). `fm.decide.waivers` (#21): ranks (add, drop) pairs by value over replacement with a FAAB bid heuristic inside `faab_bid_cap`, `find_untouchables` protected, timed to the league's waiver run from `settings.roster_lock_type` (a free agent whose game this period has started is skipped with a reason; an `UNKNOWN` roster lock type skips every candidate with a warning), a per-matchup-week budget from `max_transactions_per_week − acquisitions_this_week` that agrees with `evaluate()`, emitting `WaiverPayload` / `AddDropPayload` as `("nfl", "waivers")`. `fm.model.availability` (#22): `p_active` from the effective designation (the NBA official injury report replaces ESPN's status for that day's game, matched by name, team and US Eastern day; "Available" clears a stale OUT), hard zeros (inactive, no team, no game, ruled out), NFL practice trends (the latest non-rest day sets the shift, ±0.05 per level gained or lost since the week's first day, questionable-specific tables, veteran rest days ignored; `assess_stored` keeps the week's practice log in the period's row because nflverse only keeps the latest status), Claude news signals (each clamped to ±0.3 × confidence, the latest per kind, cited and finite only, published after the team's previous game and no later than `as_of` or kickoff, the total clamped to ±0.3 again, `inputs["news"]["before"]` kept, every clamp and rejection logged), each step recorded in the row's `inputs`; `plan_pivots` values late-game swaps (a status is known 90 min before an NFL kickoff, 30 before an NBA tip; a bench player covers a same-slot starter who is still unlocked then and locks strictly earlier) by optimal matching. `fm.sources.news` (#23): ESPN's public news API and RotoWire's RSS with a browser user agent, a 10-minute poll floor served from the cache even with `force`, the last good copy on a failed refresh, dedupe by (source, id) and by text within 3 days, `poll_news(sport)`; `fm.model.relevance`: `relevance_for` tags our roster, the opponent's (`opponent_from(matchups, team_id)`), the top free agents by ESPN season projection under the league's scoring (a summed per-category z-score stand-in for category leagues) and trade targets, `ingest_news` stores items (RotoWire players matched to ESPN ids by name) and `relevant_news` returns the stored items about relevant players with who and why. `fm.model.categories` (#24): categories, their order and negatives from the league settings (`isReverseItem`), volume-weighted rate categories for all 16 ESPN rate stats, z-scores and G-scores (`√(σ² + κτ²)`, κ = 2N/(2N−1); ## Phase 6 — DONE
Built: the NFL manager end to end plus NBA daily decisions.

- **CLI (#26).** `fm status|lineup|waivers` (src/fm/commands/advise.py + src/fm/render/) render engine numbers and policy verdicts, snapshot-tested against the fixture-backed home `tests/fixtures/home/` (config.toml, state.db, cache, snapshots; rebuilt by build.py; use `FM_CONFIG_DIR=tests/fixtures/home`).
- **Add/drop and waivers (#27).** `fm.browser.flows.add_drop` and `waiver` cover the free-agent add/drop, the waiver claim with a bid, and cancel. They run in API mode with a UI fallback (player-list and rosterfix selectors are registered, with the `players_page_url` / `roster_fix_url` builders). Preconditions refuse duplicate claims and moves past `plugin.transaction_cutoff`.
- **Tick and scheduler (#29).** `fm.jobs.tick` and `deadlines` run each tick in order:
  - sync when stale;
  - `reconcile_executions`, `expire_due`, then `auto_approve_due` (T-15, never while paused);
  - due registered decisions, once per window. The windows are PRE_LOCK → `LINEUP_DECISIONS`, PRE_ROSTER_LOCK → `ACQUISITION_DECISIONS`, PRE_WAIVER → waivers and PERIOD_OPEN → all. The opponent goes to `OPPONENT_DECISIONS` through `fm.espn.calendar.matchup_period_of`;
  - executions with session checks;
  - phone pushes and missed-window alerts.

  The tick imports every decision module (nfl `lineup`/`waivers`, nba `lineup_daily`/`streaming`) so their registrations exist. `fm schedule install|uninstall|show` uses schtasks with a `.cmd` wrapper.
- **Advisor client (#30).** `fm.advisor.client` uses claude-opus-5-5 with per-worker effort, `messages.parse`, `stop_reason` checks, a refusal fallback, caching, Batches, `llm_usage` and a daily budget cap. `fm.advisor.news_triage` stores bounded, cited news signals for `availability.assess`.
- **Season simulator (#32).** `fm.model.simulate` runs a seeded Monte Carlo for P(win week), playoffs, bye and title, plus per-category NBA probabilities.
- **NBA daily lineups and streaming (#31).**
  - **Calendar.** `fm.espn.calendar` loads `data/calendars/<game>_<season>.json` (ESPN web-client calendars; refresh with `capture.py webclient` + `extract_calendar`). `league_matchup_days`, `matchup_scoring_periods` and `matchup_period_of` resolve NBA matchup weeks, and `policy.week_filter` counts the matchup's days, or the trailing 7 without a calendar.
  - **Daily lineups.** `fm.decide.lineup_daily.plan_week` solves the matchup week as a staged `scipy.optimize.milp`: playing fills, then value, then fewest moves. Locks and IR are hard, games-played caps are spent on the best days, and `p_active` comes from the availability row (official report), never ESPN's raw status. Category leagues are swing-weighted (Φ(Δμ/σ)) against the opponent. Registered as `("nba","lineup_daily")`.
  - **Streaming.** `fm.decide.streaming` ranks streamers by `marginal_lineup_value`, and `plan_streams` runs a beam DP over (roster, acquisitions used) re-valued exactly by `plan_week`. Protected players are never dropped: untouchables, IR, players in open proposals, the core, and `protected`. The budget is min(`matchup_limit_for(days)`, policy) − used, and adds land before the first tip (`transaction_cutoff`). Unvalued players (no projection) and players in open lineup proposals are never dropped. A drop worth more per game than the add is refused. Only today's add/drop is proposed. Registered as `("nba","streaming")`.
- **Selector canary (#28).** `fm.browser.canary` is registry-driven and read-only: goto and count only, never clicking. An ALWAYS selector that is missing or a NEVER marker that shows is drift, and SOMETIMES never alerts. Every read view is re-parsed through `EspnClient`. Each `WebPage` needs a `PAGE_ADDRESSES` entry. `fm canary [--fixtures DIR] [--alert/--no-alert]` sends one `send_alert` for live drift.
- **Backtest (#33).** `fm.eval.backtest` provides `BacktestData` (`with_source` / `without_source` / `restrict_to`), `with_blend`, and `run_backtest(..., restrict_to_common=)` → `BacktestReport`. That report holds projection MAE by position, lineup efficiency and start/sit regret per source, plus the manager's baseline. `load_fixture` reads `tests/fixtures/backtest/<sport>/backtest.json` (format in that README) and `load_store_data` reads the synced store. It skips the current period and periods whose actuals predate their last game. NFL points leagues only. #39, #42 and #43 plug sources in through `with_source`.
- **FAAB bid model (#34).** `fm.decide.faab` fits winning bids as budget fractions from executed WAIVER records, as a quantile of claim strength shrunk toward the heuristic (n/(n+8)). It is monotone by construction and falls back to the heuristic with a warning below 5 non-zero bids. `Bidding` deducts bids pledged by open waiver proposals, and by verified (submitted) claims until a sync after their run. History comes from `raw_snapshots` kind `mTransactions2`, which `fm sync` does not capture yet.
- **Rankings (#35).** `fm.decide.rankings.rank_league` and `fm rankings [--fixtures DIR] [--out DIR]` write `rankings_<league>.csv` with NFL ROS/VOR from `load_valuation(include_rostered=True)`, NBA points from scheduled games, and NBA categories as G/z per category.

Patterns:

- Decisions accept `(store, config, league_row, *, schedule, now, opponent_team_id=…)`; the tick passes only the keywords each accepts.
- Every new module goes in `tests/test_public_names.py` MODULES.
- `--fixtures DIR` commands reuse `fm.commands.execute.RecordedViews` behind an httpx MockTransport.
